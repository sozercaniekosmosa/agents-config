# Конструктор навыков: стандарт самообновляемого навыка

> [!IMPORTANT]
> Навык собирается по брифу: назначение + база. Контракт самообновления вшивается автоматически и не обсуждается.
> Готовый навык синхронизирует себя сам; вопрос пользователю — только по пунктам эскалации.

## Назначение

- Вход: описание задачи и база — на чём навык стоит (модули/файлы, скрипты, внешние доки, чистая процедура).
- Выход: пакет `.agents/skills/<name>/` — `SKILL.md`, `references/contracts.md`, `scripts/track.cjs`, `state/state.json`, `CHANGELOG.md`.
- Жёстко вшивается: самостоятельное обновление спецификации без уведомлений + эскалация спорных пунктов.
- Проверка: `forge check` валидирует все управляемые навыки на соответствие стандарту.

## Быстрый старт

| Команда | Действие |
| --- | --- |
| `node .agents/skills/forge/scripts/forge.cjs spec` | эталонный бриф (JSON) |
| `... new --spec <file.json> [--out dir] [--force] [--dry-run]` | собрать навык |
| `... check [--root dir] [--json]` | аудит управляемых навыков; exit 1 = нарушения |
| `... update "<что изменилось>"` | манифест + AUTO-блок + CHANGELOG |
| `... upgrade <skill>` | вшить автономию и маркер управляемости в существующий навык |

## Бриф (минимум)

1. **Назначение** — 1–2 предложения: какую задачу решает навык и чем результат отличается от «просто сделать руками».
2. **База** — на чём стоит: пути модулей/файлов, существующие скрипты, внешние доки, либо чистая процедура без кода.
3. **Имя** — `kebab-case`; если не задано, выводится из триггера/назначения.

Остальное выводится дефолтами: триггеры, инварианты, гейты, границы, ловушки.
Вопрос — только если база неоднозначна (два кандидата, конфликтующие владельцы) или назначение допускает несовместимые трактовки.

### Трактовки базы

| База | tracking | Что получает навык |
| --- | --- | --- |
| Код/модули проекта | `track` | baseline файлов, дрейф, инвентарь, LOC/TODO/баррели |
| Скрипты, доки, процедура | `spec` | протокол, контракт и CHANGELOG без baseline |

## Конвейер

1. Бриф → нормализация: имя, триггеры, `tracking`, список модулей, дефолты.
2. `new` собирает пакет по шаблону (`references/template.md`).
3. Сверить карту базы: пути существуют, владелец один, слои не нарушены.
4. Дописать «Ловушки» и «Гейты» под конкретную базу — только доказанные ограничения, без вымысла.
5. `node .agents/skills/<name>/scripts/track.cjs --update "baseline"` (track) или `forge update "<name>: baseline"` (spec).
6. Прогнать гейты навыка и `forge check`.
7. Запись в реестр эволюции: `node .agents/skills/observer/scripts/observer.cjs --log-history <scope> <trigger> <improvement>`.

## Обязательные требования к созданному навыку

- Блок автономии между маркерами `FORGE:AUTONOMY` — канонический текст, менять нельзя.
- Полный список эскалации (6 пунктов из `references/template.md`): контракт, неоднозначность, эталон, данные, красный гейт, обход правил.
- Протокол: вход → правки → проверки → синхронизация спецификации в том же проходе.
- `tracking=track`: `scripts/track.cjs` с `--check/--report/--audit/--update`, baseline в `state/state.json`, AUTO-блок в `SKILL.md`.
- Жёсткие инварианты и «Границы»: что навык не делает и что не переписывает.
- Zero Dead Code: без заглушек, пустых секций и `// TODO`.

## Верификация

1. `node .agents/skills/forge/scripts/forge.cjs check` — структура и автономия всех управляемых навыков.
2. Сгенерированный `scripts/track.cjs --check` — дрейф нулевой.
3. `node .agents/skills/check/arch-check.cjs` — если навык трогает `src/**`.
4. Гейты из брифа — по возрастанию стоимости.

> Автономия: навык обновляет себя сам — без уведомлений, без пауз на согласование.
> Синхронизация спецификации (`SKILL.md`, `references/contracts.md`, `CHANGELOG.md`, `state`) — в том же проходе, что и работа.

### Автономно (без вопроса)

- Правки спецификации, контракта, ловушек и рецептов по фактам работы.
- Гейты запускаются автономно; красный гейт чинится, пока причина выводится из контракта.
- Дрейф файлов относительно baseline на входе — работа, а не повод спросить.
- Реестр эволюции и `CHANGELOG.md` пишутся сразу.

### Эскалация (стоп, один вопрос, до ответа — только read-only)

- Ломается публичный контракт или совместимость (данные, API, legacy).
- Поведение неоднозначно: варианты равно соответствуют правилам.
- Меняется эталон проверок (golden/baseline ожидаемых результатов).
- Деструктивные операции с данными или внешними системами.
- Проверка красная, причина не выводится из правил.
- Требуется обойти жёсткое правило или инвариант.

Формат эскалации: 1 вопрос · варианты · рекомендация · последствие выбора.

## Петля эволюции

- Дефект стандарта (проверка пропускает плохой навык) → правка `forge.cjs` + `references/template.md` + CHANGELOG.
- Новый обязательный раздел шаблона → `TEMPLATE_VERSION + 1`; существующие навыки добирают через `upgrade`.
- Устаревшее требование → удалить, не копить дубли.

## Границы

- `new` пишет только каталог навыка; существующий каталог не перезаписывает без `--force`.
- `check` — read-only; `update` пишет только `state/state.json`, AUTO-блок, `CHANGELOG.md`.
- `upgrade` меняет только блок автономии и маркер управляемости в целевом `SKILL.md`; `CHANGELOG.md` создаёт, если его нет.
- Навык не пишет доменный код за пользователя: генерирует спецификацию и инструменты, реализация — отдельная задача.
