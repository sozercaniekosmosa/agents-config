# Стандарт сгенерированного навыка

Справочник `forge`: что именно собирается, какие поля обязательны, чем проверяется.
Канонический источник — этот файл; `forge.cjs` реализует его и валидирует результат.

## 1. Состав пакета

| Файл | Назначение | Обязателен |
| --- | --- | --- |
| `SKILL.md` | контракт, протокол, инварианты, автономия | да |
| `references/contracts.md` | карта базы, поля, ловушки, рецепты | да |
| `scripts/track.cjs` | baseline/дрейф/аудит/синхронизация | при `tracking=track` |
| `state/state.json` | baseline: хэши и LOC файлов базы | при `tracking=track` |
| `CHANGELOG.md` | append-only журнал изменений | да |

- Имя каталога = `name` из фронтматтера = `kebab-case`, 2–32 символа.
- Никаких заглушек: пустые секции и `// TODO` запрещены.
- Приватные имена модулей живут в `contracts.md`, общие правила — в `SKILL.md` (generalization filter).

## 2. Скелет `SKILL.md`

| Порядок | Раздел | Содержимое |
| --- | --- | --- |
| — | фронтматтер | `name`, `description` (2–4 строки + триггеры), `argument-hint` |
| 0 | `<!-- FORGE:MANAGED mode=track\|spec -->` | маркер управляемости |
| 1 | `# <Заголовок>: контракт и протокол` | заголовок |
| 2 | `> [!IMPORTANT]` | вход/выход протокола, автономия, эскалация |
| 3 | `## Назначение` | что делает, чем полезен, чем проверяется |
| 4 | `## Быстрый старт` | таблица команд и действий |
| 5 | AUTO-блок | статистика baseline (только `track`) |
| 6 | `## Карта базы` | что покрывает навык, владелец, слои |
| 7 | `## Протокол обработки` | вход → правки → верификация → синхронизация → петля |
| 8 | `## Жёсткие инварианты` | нумерованный список, проверяемые утверждения |
| 9 | `## Гейты` | команды проверок по возрастанию стоимости |
| 10 | `## Ловушки` | только доказанные ограничения |
| 11 | блок автономии | маркеры `FORGE:AUTONOMY` + канонический текст |
| 12 | `## Петля эволюции` | как навык улучшает сам себя |
| 13 | `## Границы` | что навык не делает |

## 3. Канонический блок автономии

Текст обязателен целиком; `forge check` сверяет пункты эскалации с этим эталоном.
Маркеры: `<!-- FORGE:AUTONOMY:START -->` … `<!-- FORGE:AUTONOMY:END -->`.

```md
> Автономия: навык обновляет себя сам — без уведомлений, без пауз на согласование.
> Синхронизация спецификации (`SKILL.md`, `references/contracts.md`, `CHANGELOG.md`, `state`) — в том же проходе, что и работа.

### Автономно (без вопроса)

- Правки спецификации, контракта, ловушек и рецептов по фактам работы.
- Гейты запускаются автономно; красный гейт чинится, пока причина выводится из контракта.
- Дрейф файлов относительно baseline на входе — работа, а не повод спросить.
- Реестр эволюции и `CHANGELOG.md` пишутся сразу.

### Эскалация (стоп, один вопрос, до ответа — только read-only)

- Ломается публичный контракт или совместимость (данные, API, legacy).
- Поведение неоднозначно: варианты равно соответствуют правилам.
- Меняется эталон проверок (golden/baseline ожидаемых результатов).
- Деструктивные операции с данными или внешними системами.
- Проверка красная, причина не выводится из правил.
- Требуется обойти жёсткое правило или инвариант.

Формат эскалации: 1 вопрос · варианты · рекомендация · последствие выбора.
```

## 4. Бриф (`forge spec`)

```json
{
  "name": "wizard",
  "title": "Мастер карточки",
  "purpose": "Контракт и протокол изменений модуля cardWizard: карта слоёв, инварианты, гейты.",
  "tracking": "track",
  "basis": {
    "modules": ["src/shared/cardWizard", "src/store/cardWizard", "src/db/cardWizard.ts"],
    "ext": [".ts", ".tsx"],
    "maxLoc": 500
  },
  "triggers": ["/wizard", "мастер карточки", "измени мастера"],
  "invariants": [
    "Тексты и правила берутся из профиля, дефолт — в общем слое.",
    "Новые поля сессии читаются старыми записями (default при разборе)."
  ],
  "gates": ["npm run typecheck", "npm run build"],
  "boundaries": ["Не меняет схему БД вне JSON-сессии."]
}
```

| Поле | Обязательно | Дефолт |
| --- | --- | --- |
| `name` | да | — |
| `purpose` | да (≥ 10 символов) | — |
| `basis.modules` | при `tracking=track` | `[]` |
| `tracking` | нет | `track` |
| `basis.ext` | нет | `.ts .tsx .mjs .cjs .js` |
| `basis.maxLoc` | нет | `500` |
| `triggers` | нет | `/<name>` |
| `invariants` | нет | 3 общих инварианта |
| `gates` | нет | `tsc --noEmit`, `arch-check.cjs` |
| `boundaries` | нет | 2 общих ограничения |

## 5. Контракт `scripts/track.cjs`

| Команда | Действие | exit |
| --- | --- | --- |
| без флага / `--check` | дрейф относительно `state/state.json` | 1 при дрейфе |
| `--report` | инвентарь: модули, файлы, LOC, крупнейший | 0 |
| `--audit [--strict]` | LOC-лимит, TODO/FIXME/HACK, баррели `src/**` | 1 при ошибке (strict: и при предупреждении) |
| `--update "<note>"` | перезапись baseline, AUTO-блок, CHANGELOG | 0 |

- `CONFIG` в шапке: `name`, `title`, `marker`, `maxLoc`, `modules`, `ext`.
- Пишет только `state/state.json`, AUTO-блок `SKILL.md`, `CHANGELOG.md`.
- Baseline — единственный источник правды о «что менялось»; эталон результатов проверок — отдельно и через эскалацию.

## 6. Чек-лист приёмки

1. `forge check` — зелёный.
2. `track.cjs --check` — дрейф нулевой сразу после `--update`.
3. Все `basis.modules` существуют и принадлежат одной ответственности.
4. Инварианты проверяемы: каждый либо гейт, либо явное правило.
5. Гейты дешёвые вперёд, дорогие в конце.
6. «Ловушки» содержат только наблюдавшиеся ограничения.
7. `CHANGELOG.md` получил строку о создании.
8. `SKILL.md` ≤ 200 строк, `track.cjs` ≤ 240 строк (иначе декомпозиция).
9. Триггеры не конфликтуют с существующими навыками.
10. Реестр эволюции обновлён (`observer --log-history`).

## 7. Антипаттерны

- «Предложить обновить навык», «после подтверждения пользователя», «запросить разрешение» — ломают автономию, `forge check` падает.
- Уведомления о рутинной синхронизации: CHANGELOG пишется молча.
- Инвариант без проверки и без владельца — мусор.
- Дубль протокола в `SKILL.md` и `contracts.md`: контракт живёт только в контракте, протокол — только в `SKILL.md`.
- Приватные пути/компоненты в «общих» правилах: обобщать до слоёв и контрактов.
- `// TODO` в сгенерированных файлах вместо записи в `docs/techdebt.md`.
