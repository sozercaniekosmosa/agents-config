# План реализации BFF для древа (с учетом архитектуры UI)

> [!NOTE]
> - **Статус плана:** `[BACKEND_READY]`
> - **Версия Backend/Gateway:** `gpna-asodu-tech-gateway 1.3.7` (OpenAPI/Swagger 1.3.6)
> - **Спецификация в Confluence:** RFC-001 Draft #2 (ID: `1049117`), план внедрения (ID: `1049120`), Задачи INHOUSE-50, INHOUSE-51
> - **Дата актуализации:** 2026-10-27
> - **Ключевые архитектурные изменения (Gateway 1.3.7):**
>   1. Ручки `tree/models` и `tree/children` переведены в статус `[DEPRECATED]`.
>   2. Внедрен единый унифицированный поуровневый эндпоинт `GET /api/bff/bff/v1/tree?parentId=<guid>` (без parentId или `00000000-0000-0000-0000-000000000000` — модели; id модели — корни модели; id экземпляра — его дети). Ответ: `{ items, totalCount }`.
>   3. Внедрен эндпоинт хлебных крошек `GET /api/bff/bff/v1/tree/path/{id}` для мгновенного резолва deep-link (1 req вместо цепочки до 15).
>   4. Внедрен эндпоинт поиска `GET /api/bff/bff/v1/tree/search?q=<str>&modelId=<guid>&take=<n>`.
>   5. В каждый элемент `BffTreeItem` добавлены поля `objectModelId`, `modelPrototypeId`, `prototypeNodeId` (полная выгрузка 5.3 МБ экземпляров для модалки создания больше не требуется).
>   6. Мутации (CUD) сохранены в прямом прокси НСИ (`/api/nsi/...`); для корней моделей в НСИ передается `parentId: null` (в BFF у корня `parentId = modelId`).
>   7. Ошибки стандартизированы по RFC-7807 (`ProblemDetails`), при 502 (НСИ недоступна) на клиенте `retry: false` (BFF уже выполнил внутренние повторы).

## 1. Анализ узких мест текущей реализации (UI → BFF)

### 1.1. Заменяемые API и UI-модули

- **Целевой UI-модуль**: Виджет боковой панели дерева объектов (`src/widgets/object-model-sidebar` и его хук `use-sidebar-tree.tsx`).
- **Заменяемые Downstream API (идут под замену на клиенте)**:
  - `GET /api/nsi/ObjectInstances` без параметров (полная выгрузка всех экземпляров, 5.3 МБ трафика).
  - Каскадные рекурсивные вызовы `GET /api/nsi/ObjectInstances?Id=...` в `resolvePath` (до 15 последовательных запросов при открытии по ссылке).
  - Чанкирование `refreshExpandedNodes` по 3 запроса из-за риска 429 на Nginx.
  - `GET /api/nsi/ObjectModels` (корневой список моделей).
- **Сохраняемые Downstream API (Мутации через прокси НСИ)**:
  - `POST /api/nsi/ObjectInstances` и `POST /api/nsi/ObjectModels` (создание).
  - `PATCH /api/nsi/ObjectInstances` и `PATCH /api/nsi/ObjectModels` (редактирование).
  - `DELETE /api/nsi/ObjectInstances` и `DELETE /api/nsi/ObjectModels` (удаление).

### 1.2. Технические проблемы

- **N+1 запросы при поиске пути (Deep-Link)**: Открытие ссылки на узел глубиной 4 требовало 12 запросов (9 последовательно), перекачивая 10.7 МБ за ~2.4 с. С BFF путь возвращается одним запросом `GET /tree/path/{id}`.
- **Избыточный трафик (Overfetching)**: Ради поиска прототипов для формы «Добавить объект» скачивалась вся база экземпляров. В `BffTreeItem` метаданные прототипов уже включены в каждый узел.
- **Сложный клиентский State Management**: Ручные структуры `childrenMap` и `treeNodeDataMap` дублировали кэш TanStack Query, а синхронизация требовала подписки на `getQueryCache().subscribe`.

## 2. Проектирование API (Маршрутизация в gateway 1.3.7)

### 2.1. Эндпоинты чтения (BFF Gateway)

1. **`GET /api/bff/bff/v1/tree?parentId=<guid>`**:
   - Плоский список одного уровня дерева, отсортированный по имени на стороне сервера.
   - Без `parentId` (или `00000000-0000-0000-0000-000000000000`) → список объектных моделей.
   - `parentId = {modelId}` → корневые экземпляры модели.
   - `parentId = {instanceId}` → дочерние экземпляры узла.
   - Ответ: `{ items: BffTreeItem[], totalCount: number }`.
2. **`GET /api/bff/bff/v1/tree/path/{id}`**:
   - Хлебные крошки: путь от модели до узла одним запросом.
   - Ответ: `{ path: BffTreeCrumb[] }`.
3. **`GET /api/bff/bff/v1/tree/search?q={str}&modelId={guid}&take={1..200}`**:
   - Поиск экземпляров по части имени (q от 2 символов).
   - Ответ: `BffTreeSearchResult[]`.
4. **Устаревшие эндпоинты (`[DEPRECATED]`)**:
   - `GET /bff/v1/tree/models` → заменен на `GET /tree`.
   - `GET /bff/v1/tree/children?keys=...` → заменен на `GET /tree?parentId=...`.

### 2.2. Мутации (CUD)

- Мутации остаются на прямом прокси НСИ (`/api/nsi/...`).
- **Специфика parentId**: в BFF у корней модели `parentId = modelId`. При отправке создания/редактирования корня в НСИ на клиенте передается `parentId: null`.
- После успешной мутации клиент точечно перезапрашивает только измененный уровень `tree?parentId=...`.

## 3. Контракты BFF (TypeScript / Zod)

```typescript
/**
 * 3.1. Элемент уровня дерева.
 */
export interface BffTreeItem {
  id: string;
  type: string; // "model" | "instance"
  title: string;
  isLeaf: boolean;
  parentId?: string | null;
  objectModelId: string;
  modelPrototypeId?: string | null;
  prototypeNodeId?: string | null;
}

/**
 * 3.2. Ответ поуровневой загрузки дерева (GET /bff/v1/tree).
 */
export interface BffTreeLevelResponse {
  items: BffTreeItem[];
  totalCount: number;
}

/**
 * 3.3. Элемент хлебных крошек (GET /bff/v1/tree/path/{id}).
 */
export interface BffTreeCrumb {
  id: string;
  type: string;
  title: string;
}

export interface BffTreePathResponse {
  path: BffTreeCrumb[];
}

/**
 * 3.4. Результат поиска (GET /bff/v1/tree/search).
 */
export interface BffTreeSearchResult {
  title: string;
  path: string;
  instanceId: string;
  objectModelId: string;
}

/**
 * 3.5. Стандартизированная ошибка RFC-7807 (ProblemDetails).
 */
export interface ProblemDetails {
  type?: string | null;
  title?: string | null;
  status?: number | null;
  detail?: string | null;
  instance?: string | null;
}
```

## 4. Архитектура слоя BFF (Gateway)

- **Агрегация и кэширование**: BFF берет на себя сортировку и сборку плоских уровней.
- **Resilience (Отказоустойчивость)**: При недоступности downstream НСИ шлюз выполняет внутренние повторные попытки перед возвратом `502 Bad Gateway`.
- **Клиентская стратегия при 502**: На фронтенде выставляется `retry: false` для предотвращения шторма повторов, а пользователю отображается `ProblemDetails.title`.
- **Token Relay**: Шлюз автоматически пробрасывает JWT-токен пользователя в downstream-сервисы.

## 5. Интеграция UI (FSD сущность и рефакторинг сайдбара)

### 5.1. Сущность `src/entities/tree` (ACL Слой)
- `model/tree.contract.ts` — Zod runtime-валидация ответов BFF.
- `model/tree.dto.ts` — DTO по Swagger 1.3.6.
- `model/tree.model.ts` — доменные типы `TreeNodeItem`, `TreePathCrumb`.
- `model/tree.mapper.ts` — преобразование в UI-формат `TreeViewItem`.
- `api/tree.api.ts` — методы `getTreeLevel`, `getTreePath`, `searchTree`.
- `api/tree.queries.ts` — TanStack Query options (`retry: false`, `staleTime: 30s`).

### 5.2. Рефакторинг `src/widgets/object-model-sidebar`
- Замена `models` на `treeLevelQueryOptions(undefined)`.
- Переписывание `resolvePath`: 1 вызов `getTreePath(selectedNodeId)` + параллельный `Promise.all` для загрузки уровней предков.
- Устранение гонок (Race Conditions) через проверку `isActive` / `AbortController`.
- Извлечение данных для формы «Добавить объект» из `item.data` выбранного узла.
- При мутациях корней в НСИ — передача `parentId: null`.
- Точечная инвалидация измененного уровня `tree?parentId=...`.

## 6. Завершение и Очистка (Zero Dead Code)

- Полное удаление вызова `useObjectInstancesQuery()` без параметров в сайдбаре.
- Удаление неиспользуемых импортов из `@/entities/object-instance` (`objectInstancesQueryOptions`, `objectInstanceChildrenQueryOptions`, `mapChildrenCache`, `OBJECT_INSTANCE_ROOT_QUERY_KEY`).
- Удаление каскадного цикла `while` в `resolvePath`.
- Удаление подписки `getQueryCache().subscribe` по кэшу `objectInstances.children`.
