> - **Дата актуализации:** 2026-10-16
> - **Ключевые архитектурные изменения относительно этого исторического плана:**
>   1. Единый смарт-эндпоинт `GET /bff/tree/nodes` заменен на 4 гранулярных эндпоинта (`tree/models`, `tree/children`, `tree/path`, `tree/search`).
>   2. Мутации оставлены в прямом прокси НСИ (`/api/nsi/...`), каскадное удаление в BFF исключено.
>   3. В `BffTreeNode.meta` добавлены поля `path` (иерархический путь) и `modelPrototypeId` (для экземпляров).

## 1. Анализ узких мест текущей реализации (UI → BFF)

### 1.1. Заменяемые API и UI-модули

- **Целевой UI-модуль**: Виджет боковой панели дерева объектов (`src/widgets/object-model-sidebar` и его хук `use-sidebar-tree.tsx`).
- **Текущие Downstream API (идут под замену на клиенте)**:
  - `GET /api/nsi/ObjectModels` (получение корневых узлов-моделей).
  - `GET /api/nsi/ObjectInstances` (каскадные запросы получения дочерних элементов и поиска пути).
  - `DELETE /api/nsi/ObjectModels` и `DELETE /api/nsi/ObjectInstances` (ручной обход дерева для каскадного удаления).
  - Эндпоинты `POST`/`PUT` для создания/обновления моделей и инстансов.

### 1.2. Технические проблемы (Архитектурные узкие места)

- **N+1 запросы при поиске пути**: `resolvePath` делает до 15 последовательных запросов (`queryClient.fetchQuery`) для нахождения корня узла. BFF должен возвращать полный путь/хлебные крошки одним запросом.
- **Обход лимитов (429 Too Many Requests)**: `refreshExpandedNodes` грузит дочерние узлы чанками по 3 запроса из-за ограничений Nginx. BFF должен поддерживать bulk-загрузку узлов или отдавать поддерево за 1 запрос.
- **Сложный State Management**: `childrenMap` и `treeNodeDataMap` дублируют состояние TanStack Query, а синхронизация идет через ручную подписку на кэш (`getQueryCache().subscribe`).
- **Тяжелое удаление**: `performDelete` вручную обходит кэш и удаляет ключи. BFF должен выполнять каскадное удаление и возвращать статус для простой инвалидации корня.

## 2. Проектирование API (Маршрутизация)

- **Цель**: Максимально абстрагировать UI от домена бэкенда. UI оперирует только абстрактным понятием "Узел" (Node).
- **Шаги (Чтение - Единый Smart-Эндпоинт)**:
  - **`GET /bff/tree/nodes`** — универсальный эндпоинт, который сам определяет формат ответа на основе Query-параметров:
    - _Без параметров_ → возвращает только корни (для пустого старта).
    - `?parentId={id}&page={n}` → ленивая загрузка ветки (Lazy Loading).
    - `?selectedId={id}` → возвращает готовое дерево от корней с раскрытым путем до выбранного узла (полностью заменяет `/init` и `/path`).
    - `?search={text}` → возвращает плоский список или отфильтрованное поддерево.
  - **Итог**: Для TanStack Query на UI нужен всего **ОДИН** `useQuery`, который реактивно реагирует на изменение стейта (фильтров/выделения). Убивает всю сложную оркестрацию запросов на фронтенде.
- **Шаги (Мутации - Унифицированные)**:
  - `POST /bff/tree/nodes` — создание узла (BFF сам решает, модель это или инстанс, на основе payload: `type: "model" | "instance"`).
  - `POST /bff/tree/nodes/{id}/copy` — копирование узла (BFF сам вызывает нужный downstream-сервис для модели или объекта).
  - `PATCH /bff/tree/nodes/{id}` — обновление узла (переименование, перенос).
  - `DELETE /bff/tree/nodes` — bulk-удаление по массиву ID.

## 3. Контракты BFF (TypeScript / Zod)

- **Цель**: Строгие контракты для предотвращения техдолга (Discriminated Unions, meta для UI).

```typescript
/**
 * 3.1. Базовая модель узла.
 * Расширяемость: поле `meta` позволяет добавлять любые данные для UI (иконки, статусы),
 * не меняя основной контракт и избегая жесткой привязки (Tech Debt Protection).
 */
export interface BffTreeNode {
  key: string;
  title: string;
  isLeaf: boolean;
  type: "model" | "instance";
  parentId: string | null;
  children?: BffTreeNode[];
  meta?: Record<string, unknown>; // Свободный словарь для кастомных нужд UI
}

/**
 * 3.2. GET /bff/tree/nodes
 */
export interface GetTreeNodesRequestParams {
  parentId?: string;
  selectedId?: string;
  search?: string;
  page?: number;
  size?: number;
}

export interface GetTreeNodesResponse {
  items: BffTreeNode[];
  totalCount: number;
}

/**
 * 3.3. POST /bff/tree/nodes
 * Расширяемость: Использование Discriminated Union вместо Record<string, unknown>.
 * Защищает от слабо-типизированного кода (Any) и упрощает безопасное удаление
 * или добавление новых типов узлов в будущем.
 */
export type CreateTreeNodeRequest =
  | { type: "model"; name: string; parentId: null /* специфика модели */ }
  | { type: "instance"; name: string; parentId: string; templateIds: string[] /* специфика инстанса */ };

export type CreateTreeNodeResponse = BffTreeNode;

/**
 * 3.4. POST /bff/tree/nodes/{key}/copy
 */
export interface CopyTreeNodeRequest {
  targetParentId: string | null;
}

export type CopyTreeNodeResponse = BffTreeNode;

/**
 * 3.5. PATCH /bff/tree/nodes/{key}
 */
export type UpdateTreeNodeRequest =
  | { type: "model"; name?: string /* специфика модели */ }
  | { type: "instance"; name?: string; parentId?: string | null /* специфика инстанса */ };

export type UpdateTreeNodeResponse = BffTreeNode;

/**
 * 3.6. DELETE /bff/tree/nodes
 */
export interface DeleteTreeNodesRequest {
  keys: string[];
}

export interface DeleteTreeNodesResponse {
  success: boolean;
  deletedKeys: string[];
}

/**
 * 3.7. Ошибки авторизации и доступа (Auth / RBAC)
 */
export interface BffErrorResponse {
  statusCode: number;
  message: string;
  code: "UNAUTHORIZED" | "FORBIDDEN" | "INTERNAL_ERROR";
}
```

## 4. Разработка слоя BFF

- **Цель**: Создать отказоустойчивый слой агрегации данных.
- **Шаги**:
  - Настроить маршрутизацию и агрегирующие контроллеры.
  - **Слой Auth & RBAC (Критично)**:
    - Добавить Auth Middleware для валидации JWT и защиты эндпоинтов от несанкционированных мутаций.
    - Настроить Token Relay для безопасного проброса токенов в downstream-сервисы (избежание ошибок 401).
    - Внедрить RBAC-фильтрацию узлов — исключать из ответа ветки, к которым у пользователя нет доступа.
  - **Best Practices (Рекомендации на будущее)**:
    - **Observability**: Рекомендуется внедрить проброс `Request-ID` от UI до downstream для сквозного логирования (в текущем фронтенде заголовок пока не пробрасывается).
    - **Валидация**: Заложить строгую валидацию входящих payload (POST/PATCH) на стороне BFF до вызова downstream (инструмент зависит от стека будущего сервиса).
    - **AbortSignal**: Поддержать передачу сигналов отмены от UI к downstream-сервисам (на UI механизм уже знаком и точечно используется).
    - **OpenAPI**: Настроить автогенерацию Swagger-документации по контрактам (UI уже готов потреблять Swagger для MSW-моков).
    - **Безопасность**: На будущее заложить Rate Limiting для защиты от клиентского флуда.
    - **Мониторинг**: Реализовать эндпоинты `/health` и `/ready` для развертывания в K8s.
  - Реализовать вызовы к нижестоящим микросервисам (downstream).
  - **Защита от техдолга (Anti-Corruption Layer)**: BFF должен использовать паттерн Adapter/Фасад для изоляции от изменений контрактов downstream (если бэкенд поменяет `ObjectInstances`, UI-контракт `BffTreeNode` останется неизменным).
  - **Архитектурное правило**: BFF не должен ходить в БД (никакого SQL). Тяжелая логика резолва путей выполняется in-memory или делегируется downstream API.
  - Настроить обработку ошибок (Timeouts, Circuit Breaker) для защиты UI от деградации downstream-сервисов.
  - Настроить кэширование популярных/корневых узлов на уровне BFF (Redis/Memory).

## 5. Интеграция UI (Refactoring `use-sidebar-tree.tsx`)

- **Цель**: Максимально тонкий клиент, делегирование стейт-менеджмента на TanStack Query + BFF.
- **Шаги**:
  - Удалить ручные подписки `getQueryCache().subscribe`.
  - Удалить костыли с чанкированием запросов (`i += 3`).
  - Заменить каскадный цикл `while` в `resolvePath` на **1 вызов смарт-эндпоинта** с параметром `?selectedId={id}`.
  - Перейти на автоматическую инвалидацию TanStack Query вместо ручной мутации стейта (`setChildrenMap`, `treeNodeDataMap`).
  - Сохранить `useBroadcastMessage` для WS-реактивности, но кардинально упростить обработчик (просто вызов `queryClient.invalidateQueries`).
  - Настроить глобальный обработчик `BffErrorResponse` для перехвата `401` (редирект на логин) и `403` (блокировка UI).

## 6. Завершение и Очистка (Zero Dead Code)

- **Цель**: Убрать старую бизнес-логику из клиента.
- **Шаги**:
  - Полностью удалить старые мапперы в UI (`mapObjectInstance`, `mapChildrenCache`).
  - Вычистить старые `queryOptions` для прямых обращений к downstream.
  - Сократить размер хука `use-sidebar-tree.tsx` с ~600 до ~150-200 строк.
