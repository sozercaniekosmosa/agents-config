# Реестр технического долга (BFF)

Список проблемных UI-компонентов и API-цепочек, ожидающих перевода на слой BFF.
Источник правды: Confluence #1049102 («Архитектурные планы и RFC (ADR)», сводный реестр реализации BFF).

## Легенда статусов:
- `[ ]` **Backlog** (проблема выявлена, проектирование не начато)
- `[~]` **RFC / In Review** (план составлен, идет согласование контрактов)
- `[x]` **Backend Ready** (эндпоинты готовы и развернуты в шлюзе)
- `[X]` **Completed in UI** (клиентский код переписан на BFF, downstream вызовы удалены)

## Шкала приоритетов:
- **P0 (Критический)**: Блокирует базовую производительность ядра или бэкенд уже задеплоен и ожидает клиентского внедрения (Immediate ROI).
- **P1 (Высокий)**: Регулярный бизнес-сценарий операторов с массивным сетевым каскадом (10+ req) и риском падения интерфейса.
- **P2 (Средний)**: Архитектурный техдолг рантайма и транзакционной целостности, ухудшающий время старта экранов или надёжность мутаций.
- **P3 (Низкий)**: Локальные неэффективности в редких сценариях редактирования/администрирования без влияния на конечных пользователей.

## Задачи:

### 1. Object Model Sidebar Tree (`src/widgets/object-model-sidebar`)
- **Статус**: `[X]` **Completed in UI**
- **Приоритет**: **P0 (Критический)**
- **Проблема**: N+1 при `resolvePath`, чанкирование по 3, передача 5.3 МБ сырых экземпляров на клиент; цепочки запросов к НСИ (до 15 req при deep-link, 10.7 МБ, ~2.4 с).
- **Обоснование приоритета**: Блокирует базовую производительность ядра системы; бэкенд задеплоен и ожидает внедрения на клиенте.
- **Целевое решение BFF**: Гранулярные эндпоинты `tree?parentId=...`, `tree/path/{id}`, `tree/search` (развернуты в `gpna-asodu-tech-gateway 1.3.7`). Задачи INHOUSE-50, INHOUSE-51.
- **Спецификация**: Confluence RFC-001 Draft #2 (ID: `1049117`), план внедрения (ID: `1049120`), OpenAPI Swagger 1.3.6.
- **Локальный план**: `plans/bff-2026-10-08-13-45-tree-plan.md`.
- **Статус UI**: Завершено (реализованы `TASK-bff-tree-01-entity.md` и `TASK-bff-tree-02-sidebar.md`).

### 2. CEMIS: Получение метрик и трендов по элиасам (`src/entities/cemis`, `src/widgets/cemis-*`)
- **Статус**: `[ ]` **Backlog**
- **Приоритет**: **P1 (Высокий)**
- **Проблема**: Скачивание всех `PropertyTemplate` + N параллельных запросов свойств агрегатов + in-memory фильтрация + запрос телеметрии по GUID.
- **Обоснование приоритета**: Ключевой экран оперативного мониторинга (ГТЭС, насосы). Каскад из 10+ req при каждом переключении агрегата/даты.
- **Целевое решение BFF**: Смарт-эндпоинты `POST /api/bff/cemis/metrics/latest` и `/trends` по массиву элиасов без утечки внутренних GUID.

### 3. Мнемосхемы: Динамическое сопоставление привязок виджетов (`src/features/mnemonic-runtime`)
- **Статус**: `[ ]` **Backlog**
- **Приоритет**: **P2 (Средний)**
- **Проблема**: Виджеты привязаны к именам `propertyName`. Клиент выгружает свойства всех инстансов схемы, нормализует строки (`ё` → `е`) и ищет GUID для SignalR.
- **Обоснование приоритета**: Замедляет открытие и запуск реалтайм-анимации технологических схем; при десятках виджетов перегружает память браузера и затягивает подключение к WebSocket.
- **Целевое решение BFF**: Композитный эндпоинт `POST /api/bff/mnemonics/{id}/resolve-bindings` (готовый маппинг `cellId -> tagId` за 1 req).

### 4. Двухэтапная синхронизация формул после сохранения объекта (`src/features/object-instance`)
- **Статус**: `[ ]` **Backlog**
- **Приоритет**: **P2 (Средний)**
- **Проблема**: Клиентский каскад: создание инстанса → запрос свойств → запрос определений формул → мутация формулы. Ручной маппинг переменных на клиенте.
- **Обоснование приоритета**: Риск рассинхрона данных: падение промежуточного запроса оставляет объект с поврежденными расчетными переменными (отсутствие транзакционности).
- **Целевое решение BFF**: Серверное связывание и генерация формул в единой транзакции при создании/обновлении объекта НСИ.

### 5. Редактор мнемосхем: N+1 резолв пути/имени инстанса по свойству (`src/features/mnemonic-editor`, `src/widgets/mnemonic-editor-workspace`)
- **Статус**: `[ ]` **Backlog**
- **Приоритет**: **P3 (Низкий)**
- **Проблема**: По GUID тега выполняются `getObjectPropertiesByIds` → N запросов `getObjectInstanceById` ради строки `путь / имя_свойства`.
- **Обоснование приоритета**: Затрагивает только вспомогательные панели редактора мнемосхем и меню добавления в тренды; не аффектит рантайм-операторов и основной поток данных.
- **Целевое решение BFF**: Денормализация `instanceName` и `instancePath` прямо в DTO свойств (`ObjectPropertyDto`).
