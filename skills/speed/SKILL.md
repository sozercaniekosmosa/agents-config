Диагностика узких мест производительности ИИ-агента, файлового ввода-вывода (I/O), антивирусной нагрузки, индексаторов IDE и размера сессии.
Все модифицирующие действия (изменение конфигов, удаление временных файлов, системные команды) выполняются **строго после подтверждения пользователя**.

### Флаги запуска:
- `/speed` → интерактивная диагностика с выводом единой матрицы оптимизаций для подтверждения.
- `/speed --audit` → read-only аудит без предложений правок (только вывод отчета со статусами [✓], [!], [✗]).
- `/speed --clean` → режим глубокой очистки (включая удаление устаревших архивов и артефактов).
- `/speed --bench` → включение замера скорости компилятора (`tsc --noEmit`).

---

## 🛡️ Контракт безопасности и подтверждений (Confirm-Before-Action)
1. **Safety First (Маскирование вместо удаления)**: для временных каталогов (`.tmp/`, `.storage/`, локальные кэши) приоритетом является исключение из File Watcher и индексаторов IDE (`.vscode/settings.json`), а не физическое удаление файлов.
2. **Проверка привилегий ОС**: скрипт автоматически определяет права Администратора (UAC). При наличии прав команды защитника (Defender) сразу включаются в общий пул подтверждения.
3. **Единый интерактивный пакет (One-Shot Confirmation)**: рекомендации формируются в виде нумерованного списка с явной маркировкой безопасности (`[Безопасно: правка конфига]` vs `[Внимание: удаление файлов]`). Пользователь может подтвердить `Все безопасные` одной командой.

## 📋 Алгоритм работы (DAG Pipeline)

### Шаг 1. Комплексный экспресс-аудит (Read-Only)
Запуск диагностического скрипта:
```bash
node .agents/skills/speed/scripts/audit-speed.cjs [--bench] [--clean]
```
Скрипт проверяет:
1. **Контекст сессии**: размер транскрипта, объем токенов и количество шагов диалога.
2. **Антивирусная нагрузка**: проверка `Get-MpPreference -ExclusionPath` и активности `MsMpEng`.
3. **Индексация и Watcher**: наличие правил `files.watcherExclude`, `search.exclude` в `.vscode/settings.json`.
4. **VCS / .gitignore**: наличие тяжелых бинарников (>10MB, DB, дампов, архивов) вне `.gitignore`.
5. **Дисковый мусор**: наличие каталогов `.tmp/`, дублирующихся `node_modules`, устаревших архивов и раздутых кэшей библиотек.
6. **Состояние Git**: количество незакоммиченных и untracked файлов.
7. **Бенчмарк сборщика**: время компиляции проекта (`tsc --noEmit` / линтер).

---

### Шаг 2. Интерактивные шаги устранения (с подтверждением пользователя)

Агент выводит найденные проблемы со статусами `[!]/[✗]` и предлагает пользователю выбор в виде единой нумерованной матрицы:

#### А. Гигиена контекста сессии (Context Reset / Compact)
- **Условие**: шаг сессии > 50 ИЛИ объем контекста > 80k токенов.
- **Действие**: рекомендовать вызов встроенной команды `/compact` для суммаризации текущего контекста или открытие новой сессии.

#### Б. Исключения антивируса (Defender / AV Exclusion)
- **Условие**: Windows OS + путь проекта отсутствует в `Get-MpPreference -ExclusionPath`.
- **Действие**:
  - При `isAdmin: true` → предложить автоматическое выполнение `Add-MpPreference -ExclusionPath "<путь>"`.
  - При `isAdmin: false` → вывести готовую команду с пометкой для ручного запуска в окне PowerShell администратора.

#### В. Изоляция тяжелых файлов в `.gitignore`
- **Условие**: обнаружены файлы БД (`*.sqlite`, `*.db`), архивы (`*.7z`, `*.zip`) или каталоги хранилищ (`.storage/`, `*.bin`), отсутствующие в `.gitignore`.
- **Действие**: сформировать и согласовать добавление строк в `.gitignore`.

#### Г. Оптимизация File Watcher и поиска IDE (`.vscode/settings.json`)
- **Условие**: отсутствуют или неполны секции `files.watcherExclude`, `search.exclude`.
- **Действие**: внести конфигурацию исключения тяжелых папок (`node_modules`, `dist`, `.tmp`, `.storage`, `.git`).

#### Д. Очистка дискового мусора (Опционально)
- **Условие**: флаг `--clean` или явный выбор пользователя по удалению осиротевших архивов в корне.
- **Действие**: вывод точного списка файлов и запрос подтверждения на удаление.

#### Е. Гигиена рабочего дерева Git
- **Условие**: > 30 незакоммиченных или untracked файлов.
- **Действие**: предложить зафиксировать изменения (commit) либо очистить рабочее дерево.

---

### Шаг 3. Контрольный замер (Benchmark & Verification)
1. Повторный запуск `node .agents/skills/speed/scripts/audit-speed.cjs`.
2. Замер времени `tsc --noEmit` (до и после).
3. Формирование финального отчета с дельтой улучшений.

---

### Шаг 4. Петля Эволюции Навыка (Feedback Loop)
1. **Анализ сдвига**: проверка появления новых узких мест или платформ.
2. **Обобщение**: формулирование правил исключительно в доменно-нейтральных терминах (Zero Specificity Bias).
3. **Фиксация телеметрии**: запись в `.agents/evolution.json` (`node .agents/skills/observer/scripts/observer.cjs --record [intent] speed [friction]`).
