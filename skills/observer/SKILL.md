# Навык Observer (Телеметрия и Эволюция Навыков)

Подсистема непрерывного улучшения для накопления телеметрии запросов, оценки трений при выполнении задач, динамического синтеза архитектурных правил из дефектов и контроля кодовой базы.

---

## 🔑 Ключевые Принципы

1. **Токено-эффективность, Атомарность и Self-Healing Hygiene**:
   - Хранение в `.agents/evolution.json` агрегированных метрик без сырых промптов.
   - Атомарная запись через `.tmp` + `renameSync`, авто-бэкап поврежденного файла (`.corrupted.[timestamp].json`).
   - Автоматическая самодиагностика целостности структуры, валидация типов, нормализация и очистка фантомных сущностей (`--clean-telemetry`, `--prune-telemetry`).
2. **Комплексный аудит эволюции**:
   - *Skill Quality Linter*: проверка Feedback Loop (Zero Orphan Skills), лимит строк, YAML frontmatter, отсутствие сиротливых `.cjs` скриптов, запрет абсолютных путей, запрет legacy XML, Zero Specificity Bias.
   - *Dynamic Troubleshooting Harvester*: динамическая кластеризация дефектов из `TROUBLESHOOTING.md` по структурированным тегам и семантике со slug-дедупликацией правил для `docs/project-rules.md`.
   - *Tech Debt Aging & Hygiene Monitor*: контроль синтаксиса и давности записей в `docs/techdebt.md` с генерацией типизированных рекомендаций `[RESOLVE]` для элементов старше порога (дефолт 7 дней).
   - *Codebase Rule Enforcement Gate*: статический анализ AST/regex (`--verify-rules`) на соблюдение правил (Rules of Hooks с поддержкой multiline/custom hooks и изоляцией callback-областей, ACL границы для `*Dto` / `*DTO` и raw backend импортов).
   - *Upstream Sync Monitor*: контроль несохраненных изменений в `.agents/.git`.
3. **Нормализация, Таксономия и Конфигурируемость**:
   - Валидация входных данных: строгий ACL-фильтр в `record()` отсекает некорректные имена и принимает только системные навыки.
   - Поддержка весовых категорий трений (`syntax: 1`, `contract: 2`, `revert: 3`).
   - Гибкая конфигурация через `.agents/observer.config.json` (пороги запросов, времени, возраста техдолга, лимита строк).
4. **Машиночитаемый Контракт (--json) и CI/CD Gates**:
   - Поддержка флага `--json` для всех команд с чистым детерминированным выводом.
   - Строгая семантика кодов возврата: код 1 при нарушениях (`--verify-rules`, `--pre-commit`, `--audit --strict`).
5. **State-Preserving JIT-Проактивность и Авто-Резолв**:
   - При фиксации трения сохраняется снимок инцидента (`lastIncident`), доступный через команду `--incident`.
   - Автоматическое закрытие инцидента при обновлении спецификации целевого навыка.
6. **Критерии необходимости и достаточности**:
   - **Создание**: Повторяющийся паттерн req (частота >= 3) без покрытия профильными навыками.
   - **Изменение**: Системные трения (накопленный `skillFriction >= 2`) или дефекты в `TROUBLESHOOTING.md`.
   - **Удаление**: 0 вызовов за период (`totalCalls >= 15`) без принадлежности к веткам или декларативным стандартам.
7. **Разделение Потоков Непрерывного Улучшения (Dual-Stream Continuous Improvement)**:
   - **Поток общих навыков (`commonSkills` / `main`)**:
     - *Генерация*: формулируются **исключительно неспецифичные (domain-agnostic), переносимые изменения** (чистая алгоритмика, контракты слоев, протоколы взаимодействия, обработка ошибок). Доменная специфика категорически отсекается от общих навыков.
     - *Мониторинг*: непрерывное отслеживание и пресечение дрейфа специфичности; блокировка проникновения сущностей, полей данных или узких библиотек конкретного проекта в общие навыки.
   - **Поток проектной эволюции (`projectSkills` и `docs/`)**:
     - Специфические для проекта улучшения **обязаны полноценно исследоваться, генерироваться и применяться**:
       - к **проектным навыкам** (`projectSkills`, ветка проекта в git), если выявленный паттерн относится к специализированному функционалу конкретного проекта;
       - к **правилам и стандартам проекта в папке `docs/`** (`docs/project-rules.md`, `docs/architecture.md`, `docs/context.md`), если паттерн касается технологий проекта (AI, WebGPU, WASM, Canvas, SQLite), контрактов сущностей или доменных инвариантов.
     - *Мониторинг*: подсистема непрерывного улучшения активно фиксирует проектные инциденты, систематизирует их и направляет предложения строго в проектные навыки и файлы правил `docs/`.

## 🛠 Доступные CLI Команды

```bash
# 1. Зафиксировать выполненный запрос и трения (0 = без трений, >0 = ошибки/коррекции)
node .agents/skills/observer/scripts/observer.cjs --record [intent] [skill] [friction] [frictionType]

# 2. Проверить достижение порогов аудита
node .agents/skills/observer/scripts/observer.cjs --check-thresholds

# 3. Выполнить полный аудит эволюции и сформировать рекомендации
node .agents/skills/observer/scripts/observer.cjs --audit [--json] [--strict]

# 4. Проверить кодовую базу на соответствие синтезированным правилам (Exit code 1 при ошибках)
node .agents/skills/observer/scripts/observer.cjs --verify-rules [--json]

# 5. Комплексная проверка перед коммитом (гигиена + правила + техдолг)
node .agents/skills/observer/scripts/observer.cjs --pre-commit [--json]

# 6. Просмотреть текущий активный JIT-инцидент высокой сложности
node .agents/skills/observer/scripts/observer.cjs --incident [--json]

# 7. Выполнить очистку и санитацию телеметрии (Data Hygiene)
node .agents/skills/observer/scripts/observer.cjs --clean-telemetry [--json]

# 8. Выполнить ротацию и удаление устаревших паттернов
node .agents/skills/observer/scripts/observer.cjs --prune-telemetry [days] [--json]

# 9. Сгенерировать визуальный Markdown-отчет качества
node .agents/skills/observer/scripts/observer.cjs --report [outputPath]

# 10. Просмотреть историю эволюции навыков
node .agents/skills/observer/scripts/observer.cjs --history [--json]

# 11. Добавить запись в историю эволюции
node .agents/skills/observer/scripts/observer.cjs --log-history [scope] [trigger] [improvement]

# 12. Автогенерация шаблона нового навыка со скриптом и Feedback Loop
node .agents/skills/observer/scripts/observer.cjs --scaffold [skill-name]

# 13. Запуск автоматизированного тестового набора для /observer
node .agents/skills/observer/scripts/test-observer.cjs
```

## 📋 Порядок Выполнения

1. **Фиксация телеметрии**: На финальном шаге любой задачи агент регистрирует интент и валидный системный навык (`--record`).
2. **Проверка порогов и инцидентов**: При флаге `auditRequired` или наличии `lastIncident` (`--incident`) выполняется немедленный анализ.
3. **Анализ рекомендаций**:
   - `[RESOLVE]` → сформировать задачу на устранение стареющего техдолга.
   - `[RULE]` → внести синтезированное правило в `docs/project-rules.md`.
   - `[FIX-CODE]` → исправить нарушение архитектурного правила в кодовой базе.
   - `[CREATE]` / `[MODIFY]` / `[DELETE]`:
     - Для общих навыков (`commonSkills` / `main`) → генерация строго domain-agnostic предложений с мониторингом и отсечением дрейфа специфичности;
     - Для проектных навыков (`projectSkills` / ветка проекта) и правил `docs/` → генерация целевых доменно-специфичных улучшений.
4. **Автоматическое тестирование**: Запуск тестового набора (`node .agents/skills/observer/scripts/test-observer.cjs`) при любых изменениях в скриптах навыка.
5. **Петля Эволюции Навыка (Feedback Loop)**:
   - Анализ концептуальных сдвигов: проверить, затронуло ли выполнение базовые принципы observer или правил проекта.
   - При выявлении новых паттернов или правок пользователя → предложить актуализацию спецификации (`/learn` или подтверждение в чате).
