Анализ кода на соответствие таскам и правилам.
При любых ошибках/нарушениях → автозапуск `debug` (без создания TASK-планов).

### Флаги запуска:

- `/check --fast` → пропустить тесты (Vitest/Jest/Playwright) (только линт, tsc, архитектурный аудит).
- `/check --full` → принудительный полный аудит проекта (Режим C).

---

## Алгоритм работы

### Шаг 1. Статические технические проверки (ESLint, TSC)

1. **Сохранение файлов**: Перед проверкой убедиться, что все файлы в редакторе сохранены на диск.
2. **ESLint**: Выполнить линтинг измененных файлов (`npx eslint` при наличии конфигурации ESLint в проекте).
3. **TypeScript**: Запустить проверку типов (`npx tsc --noEmit` или `npx tsc -p tsconfig.app.json --noEmit` при наличии файла).
4. **Обработка сбоев**: При любых статических ошибках/нарушениях линта или типов → незамедлительно перейти к **Шагу 3 (Отладка)**.

### Шаг 2. Статический архитектурный аудит

1. Выполнить проверку кросс-модульных импортов с помощью скрипта:
   ```bash
   node .agents/skills/check/arch-check.cjs
   ```
2. Выполнить проверку остальных правил соответствия требованиям `.agents` (лимиты строк, запрет `any` и `console.log`).
3. При любых архитектурных нарушениях или падении скрипта → перейти к **Шагу 3 (Отладка)**.

### Шаг 3. Отладка и устранение ошибок (debug)

При ошибках на Шагах 1–2:

1. **Режим CFON**: В режиме подтверждения авто-модификация кода СТРОГО ЗАПРЕЩЕНА. Сформулировать точный диагноз и запросить подтверждение пользователя в чате перед применением исправлений.
2. **Режим CFOFF**: Автономный запуск `.agents/skills/debug/SKILL.md` → начать с **Этапа 0** (исследование Базы Знаний, точечные исправления).
3. Применить исправления в коде.
4. **Обязательный повторный запуск**: После успешного применения исправлений **незамедлительно перезапустить весь пайплайн проверок**, начиная с **Шага 1** (для подтверждения отсутствия регрессий в типах, линтере и рантайме).

### Шаг 4. Ограничения

- Запуск тестов (Vitest / Jest / Playwright) → строго при их наличии в проекте и с разрешения пользователя.
- Сложный рантайм-баг → инъекции логов из `debug/scripts/`.

### Шаг 5. Отчет

Вывод статусов в чат:

- `[✓]` — успешно, ошибок нет.
- `[✗]` — критические ошибки/нарушения.
- `[!]` — некритичные предупреждения.
- Указать результат работы `debug`, если он запускался.
