# Технические проверки (Technical Checks)

Инструкции по запуску технических проверок. Все архитектурные правила берутся из `docs/` (`docs/project-rules.md`, `docs/architecture.md`).

---

## 1. Область проверки

### Режим A (Task-based): Изменения по задаче
Запуск после `/resolve` или при наличии `TASK-[имя].md`. Принцип Fail-Fast:
1. **Список файлов** → `git status` / `git diff`. Без локальных изменений → сравнить ветку с `main` (`git diff main... --name-only`); на самой `main` → сравнить с предыдущим коммитом (`git diff HEAD~1... --name-only`). Пусто → переход к Режиму C.
2. **TypeScript** → `npx tsc --noEmit` (при наличии `tsconfig.app.json` → `npx tsc -p tsconfig.app.json --noEmit`). Ошибка в измененных файлах → стоп → вызов `debug`.
3. **ESLint (условно)** → `npx eslint "путь_к_файлу"` запускается **только** если `eslint` присутствует в `package.json` и в корне есть конфиг линтера; иначе шаг пропускается. Ошибка → стоп → вызов `debug`.
4. **Архитектурный контроль** → запуск `node .agents/skills/check/arch-check.cjs`. Проверяет DAG слоев из `docs/architecture.md`, запрет кросс-импортов между плагинами, изоляцию DOM/React от чистых слоев и неиспользуемые файлы. Ошибка → стоп → вызов `debug`.
5. **Тесты (условно)** → искать `*.test.ts/tsx`. Запускать **только** при наличии скрипта `test` в `package.json` и с предварительного согласия пользователя (`npm test -- "путь"` / `npx vitest run "путь"`). Сбой → стоп → вызов `debug`.
6. **Сквозной вызов (Call-Chain) и ACL** → проверить путь события: валидация схемы Zod на границе (`schema/` / `kernel/`), передача через `EventBus` / `PluginContext` в `store/` и рендеринг в `canvas/`.

### Режим B (Targeted): Точечный аудит
При запуске вида `/check [путь]`:
1. **Типы** → `npx tsc --noEmit` (фильтр ошибок по пути). Ошибка → стоп → вызов `debug`.
2. **Линтер** → `npx eslint "путь"` (при наличии eslint в проекте). Ошибка → стоп → вызов `debug`.
3. **Архитектура** → `node .agents/skills/check/arch-check.cjs` + проверка правил из `docs/` (`docs/project-rules.md`, `docs/architecture.md`, см. `./architectural_audit.md`). Нарушение → стоп → вызов `debug`.
4. **Тесты** → спросить разрешение пользователя → запустить тесты по пути при наличии тестового раннера в проекте. Сбой → стоп → вызов `debug`.

### Режим C (Full): Полный аудит проекта
При флаге `--full` или отсутствии изменений/задач:
1. **Типы** → `npx tsc --noEmit` по всему проекту. Ошибка → стоп → вызов `debug`.
2. **Архитектура и Dead Code** → `node .agents/skills/check/arch-check.cjs` (полный аудит DAG, изоляции плагинов, глубоких импортов и мертвых файлов). Ошибка → стоп → вызов `debug`.
3. **Линтер** → `npm run lint` запускается только если скрипт объявлен в `package.json`. Ошибка → стоп → вызов `debug`.
4. **Тесты** → спросить разрешение пользователя → запустить тесты проекта (`npm test`) при наличии скрипта в `package.json`. Сбой → стоп → вызов `debug`.
5. **Аудит соответствия `docs/`** → сверка измененных/новых файлов с требованиями `docs/project-rules.md` и `docs/architecture.md`. Нарушение → стоп → вызов `debug`.
