# Руководство по разворачиванию структуры и инфраструктуры (Scaffolding Guide)

Используется навыком `agents` на Этапе 4 для генерации структуры папок, начальных контрактов и настройки зависимостей под выбранный архитектурный архетип.

---

## 🏛️ 1. Общие правила генерации слоев

1. **Динамический состав**:
   - Директории создаются строго на основе согласованных слоев из `docs/architecture.md`.
   - Запрещено хардкодить статичные наборы папок.
2. **Публичные контракты**:
   - В корне каждого созданного слоя создается файл публичного контракта `index.ts`.
   - В корне `src/index.ts` создается точка входа SDK/приложения, экспортирующая публичные слои.
3. **Технический долг**:
   - При отсутствии `docs/techdebt.md` создается базовый файл реестра.
4. **Path Aliases (@/*)**:
   - Обязательная настройка плоских путей `@/*` в `tsconfig.json` (`baseUrl: "."`, `paths: { "@/*": ["src/*"] }`) и конфигураторе сборщика (`vite.config.ts` / bundler alias) для предотвращения лестниц импортов `../../`.

## 🔌 2. Спецификации генерации под архетипы

### Архетип: Microkernel + Plugins
1. **Зависимости (package.json)**:
   - Автоматически добавить пакет runtime-валидации `zod` в `dependencies`.
2. **Микроядро (`src/kernel/index.ts`)**:
   - Реализовать схему `pluginManifestSchema` на базе Zod (валидация `id`, `name`, `version`, `init`).
   - Типизировать контракты компонентов (`NodeComponentProps`, `NodeTypeRegistration`, `EdgeComponentProps`).
   - Типизировать снимок контекста окружения `EnvironmentStateSnapshot` и фасад доступа к состоянию `getState()` в `PluginContext` (актуальные сущности, режимы, параметры, селекшн, метаданные и ввод).
   - Реализовать `PluginRegistry` с поддержкой:
     - ACL-валидации манифеста через `pluginManifestSchema.safeParse()`.
     - Сохранения disposer-колбэков от `init()` и их гарантированного вызова при `unregister()`.
     - Реестра типов узлов и ребер.
     - Интеграции с поставщиком общего состояния среды (`stateProvider`).
   - Реализовать фабрику `definePlugin()`.
3. **Слой плагинов (`src/plugins/`)**:
   - Создать директорию эталонного плагина `src/plugins/default-nodes/` (или аналогичного).
   - Внутри папки плагина создать изолированную Zod-схему `schema.ts`.
   - Создать компонент и манифест плагина через `definePlugin()`.
   - Создать `src/plugins/index.ts` с экспортом плагинов и их регистрацией в `defaultPluginRegistry`.

### Архетип: Layered Engine / SDK
1. **Слои (`src/`)**:
   - Создать `core/` (чистая математика, 0 зависимостей), `schema/` (спецформат + валидация), `model/` (рантайм сущности), `canvas/`, `shared/`.
   - В `schema/` разместить схему персистентного формата данных и валидатор.
2. **ACL & Мапперы**:
   - Подготовить мапперы `schemaToDomain` и `domainToSchema` в `model/` для изоляции домена от сырых DTO.

### Архетип: Feature-Sliced Design (FSD v2)
1. **Слои (`src/`)**:
   - Создать `app/`, `pages/`, `widgets/`, `features/`, `entities/`, `shared/`.
   - В каждом слайсе создать публичный `index.ts`.
   - Запретить сквозные импорты в обход публичных контрактов.

### Архетип: Hexagonal / Clean Architecture
1. **Слои (`src/`)**:
   - Создать `domain/` (чистые сущности), `use-cases/` (сценарии и порты), `adapters/` (контроллеры и презентеры), `infrastructure/` (FS, сеть).
   - Подготовить интерфейсы портов в `use-cases/ports/`.

## 📦 3. Процедура установки зависимостей

1. Проверить целостность `package.json` с учетом добавленных библиотек валидации.
2. Проверить наличие точки входа (`main.tsx` / `App.tsx` / `index.ts`).
3. Запросить у пользователя явное подтверждение перед запуском команды установки пакетов (`npm install` / `pnpm install`).
