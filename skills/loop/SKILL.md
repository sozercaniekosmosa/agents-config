# Навык Loop (Универсальный Циклический Конвейер)

Автономный двухролевой конвейер итеративного решения задач, анализа качества и непрерывного улучшения с протоколированием диалога в корневой Markdown-журнал.

---

## 🔑 Ключевые Принципы

1. **Дуальная виртуальная пара (ЭК ↔ ИСП)**:
   - **ЭК (Эксперт-Контроллер)**: системный архитектор и ревьюер. Анализирует текущее состояние объекта на ошибки, логические дефекты, архитектурные нарушения и соответствие best-practice. Выдает строго **1 атомарную задачу** для ИСП либо констатирует завершение (`COMPLETED`).
   - **ИСП (Исполнитель)**: инженер реализации. Детерминированно выполняет поставленную задачу, запускает верификацию (`tsc --noEmit`, тесты, проверки) и формулирует краткий отчет о результате.
2. **Ведение протокола (`[TARGET]_IMPROVEMENT_LOG.md`)**:
   - При старте конвейера в корне проекта создается файл `[TARGET]_IMPROVEMENT_LOG.md` (напр. `OBSERVER_IMPROVEMENT_LOG.md` по образцу).
   - **Секция задачи в начале**: в самом начале журнала обязательно формируется блок `## 🎯 Основная Задача` (цель, контекст, ограничения, критерии готовности / DoD).
   - **Пошаговая последовательная запись**: итерации протоколируются строго по очереди по мере выполнения (`append-only`). Запрещено откладывать запись или генерировать журнал пачкой в конце.
   - **Стандарт диалогов ASD-STE100**: весь текст диалогов ЭК и ИСП в журнале ведется строго по стандарту ASD-STE100 ([short](../short/SKILL.md)) для экономии токенов и лаконичности:
     - Контролируемый словарь глаголов: `add`, `del`, `fix`, `move`, `update`, `split`, `merge`, `check`.
     - 1 мысль/факт = 1 строка (`- `), логические переходы строго через `→`.
     - Общепринятые сокращения: `cmp`, `fn`, `impl`, `err`, `req`, `res`, `config`, `doc`, `deps`.
     - Компактная адресация: `path/file.ext:L15 → [дефект/действие]`.
     - Императив / активный залог, без вежливости, вводных слов и пассивных конструкций.
3. **Детерминированный лимит N и Контрольная Точка (Checkpoint Gate)**:
   - Пользователь задает лимит циклов N (дефолт `N = 10`, если число не указано явно).
   - По достижении N итераций конвейер **обязан остановиться** и запросить решение пользователя:
     *«Выполнено N циклов. Статус: [кратко]. Продолжить еще [K] циклов или стоп?»*
   - Досрочный выход: если ЭК фиксирует 0 замечаний и полное достижение цели, статус переводится в `COMPLETED`, цикл завершается.
4. **Zero Dead Code & Quality Gate**:
   - После правок ИСП код очищается от мусора, временных заглушек и остаточных файлов.
   - Проверка типов и архитектурных правил обязательна перед фиксацией отчета итерации.

## 🛠 Синтаксис и Запуск

```bash
# 1. Запуск с дефолтным числом циклов (N = 10)
/loop [произвольная задача пользователя]

# 2. Запуск с явным числом циклов (например, 5 циклов)
/loop 5 [произвольная задача пользователя]

# 3. Автономный режим без остановок на мутации до точки останова N
/loop 10 [задача] !!!
```

## 📋 Порядок Выполнения

1. **Инициализация**:
   - Извлечь число циклов N (первое целое число в запросе или дефолт 10).
   - Сформировать имя файла журнала в корне: `[TARGET]_IMPROVEMENT_LOG.md` (напр. `OBSERVER_IMPROVEMENT_LOG.md`).
   - Инициализировать начало файла шапкой с описанием основной задачи:
     ```markdown
     # 🔄 Журнал Непрерывного Улучшения: [Название задачи/модуля]

     ## 🎯 Основная Задача
     - **Цель**: [Конкретная цель цикла по ASD-STE100]
     - **Границы и контекст**: [Область применения, затронутые модули/файлы]
     - **Критерии приемки (DoD)**: [Измеримые условия готовности]
     - **Параметры**: Лимит N = [N], Режим = [CFON/CFOFF], Статус = IN_PROGRESS

     Диалог виртуальной пары:
     - **ЭК (Эксперт-контроллер)**: системный архитектор, выявление дефектов и постановка задач.
     - **ИСП (Исполнитель)**: инженер реализации, тесты, очистка и отчеты.
     ```

2. **Итерационный цикл (`i = 1 .. N`)**:
   - Запись каждой итерации производится **немедленно по завершении шага**, строго по очереди.
   - **Шаг А (ЭК)**:
     - Оценить текущее состояние целевого модуля/кода/навыка.
     - Выявить критические дефекты, антипаттерны, неточности или пробелы.
     - Если все требования выполнены идеально и замечаний нет → зафиксировать вердикт `COMPLETED` и выйти из цикла.
     - Иначе → сформулировать задачу для ИСП строго по ASD-STE100:
       - Формат: `### 🧐 Анализ ЭК:`
       - Дефект / узкое место: `path/file.ext:L10 → [суть]`
       - Задача для ИСП: пункты действий через `add`, `del`, `fix`, `update`.
     - Немедленно дописать блок ЭК в `[TARGET]_IMPROVEMENT_LOG.md`.
   - **Шаг Б (ИСП)**:
     - Реализовать задачу ЭК (правка файлов, создание тестов, рефакторинг).
     - Выполнить проверку работоспособности (`npx tsc --noEmit`, профильные тесты).
     - Очистить временные изменения (Zero Dead Code).
     - Сформировать отчет строго по ASD-STE100:
       - Формат: `### 🛠 Ответ ИСП:`
       - Реализация: факты через `- [файл/модуль] → action`
       - Верификация: `tsc / tests / arch-check → 0 err`
       - Статус: `Выполнено` / `COMPLETED`
     - Немедленно дописать блок ИСП в `[TARGET]_IMPROVEMENT_LOG.md`.
   - **Шаг В**: Инкремент счетчика итерации. Переход к следующей итерации (Шаг А).

3. **Контрольная точка (Checkpoint)**:
   - Если итерация `i == N` и статус `IN_PROGRESS`:
     - Вывести в чат резюме проделанной работы.
     - Задать вопрос пользователю: *"Выполнен лимит из N циклов. Продолжить работу (укажите число циклов) или завершить?"*

4. **Петля Эволюции Навыка (Feedback Loop)**:
   - По завершении серии циклов зарегистрировать интент в телеметрии:
     `node .agents/skills/observer/scripts/observer.cjs --record loop:task loop 0`
   - При выявлении систематических трений или концептуальных сдвигов → предложить обновление спецификации (`/learn`).

## 📄 Пример Записи Итерации (Стандарт ASD-STE100)

```markdown
## 📌 Итерация [i/N]: [Краткое имя по ASD-STE100]

### 🧐 Анализ ЭК:
1. **Дефект**: `src/api/client.ts:L42 →` прямое использование DTO в UI store без ACL-маппинга.
2. **Задача для ИСП**:
   - `add` Zod-валидацию входящего ответа в `src/api/schema.ts`.
   - `add` маппер `mapClientDtoToDomain` в `src/api/mapper.ts`.
   - `update` store вызов на использование доменной сущности.

### 🛠 Ответ ИСП:
- **Реализация**:
  - `src/api/schema.ts` → `add` Zod-схема ответа.
  - `src/api/mapper.ts` → `add` чистый маппер `mapClientDtoToDomain`.
  - `src/store/useClientStore.ts` → `update` прием данных через маппер.
- **Верификация**: `npx tsc --noEmit → 0 err`, `arch-check.cjs → OK`.
- **Статус**: Выполнено.
```
