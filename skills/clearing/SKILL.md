# Очистка проекта от лишнего: контракт и протокол

> [!IMPORTANT]
> Инвентарь и отчёт — до любого удаления; удаление — только после присвоения класса обратимости.
> Классы `R`/`C` чистятся автономно; `D`/`P` → стоп и один вопрос по пунктам эскалации.
> Вопрос пользователю — один, с вариантами и последствием выбора.

## Назначение

- Задача: снимок дерева → классификация артефактов по обратимости → удаление не относящегося к проекту → подтверждение гейтами.
- Отличие от «удалить руками»: каждый кандидат получает класс, размер и доказательство (команда восстановления или `--refs`).
- Отличие от `/speed`: `/speed` ускоряет среду и трогает кэши пошагово; `/clearing` судит о принадлежности артефакта проекту.
- Самообновление: `SKILL.md`, `references/contracts.md`, `CHANGELOG.md` синхронизируются в том же проходе.
- Проверка: `node .agents/skills/forge/scripts/forge.cjs check`.

## Быстрый старт

| Команда | Действие |
| --- | --- |
| `node .agents/skills/clearing/scripts/scan.cjs --inventory` | объём и файлы по каталогам, присвоенный класс, пустые каталоги, подозрительные имена |
| `... --graph` | модули исходников с нулём входящих рёбер в графе импортов |
| `... --refs <path>` | где упоминается файл или каталог — доказательство «сироты» |
| `... --inventory --json` | машинный снимок для сравнения до и после прохода |

## Карта базы

Класс присваивается до удаления, а не после. Детали и приватные пути — `references/contracts.md`.

| Класс | Признак | Политика |
| --- | --- | --- |
| `R` воспроизводимое | артефакт сборки, кэш типов, кэш пакетного менеджера | удалять автономно: восстановление — одна документированная команда |
| `C` инструментальный кэш | каталог инструментов и агентов, логи модулей, атомарные `*.tmpdir/` | удалять автономно |
| `D` данные и черновики | база и её бэкапы, рабочие черновики, архивы исходников | эскалация: невоспроизводимо |
| `P` содержимое проекта | исходники, документация, скрипты, статика, `[module]/guide.md`, `[module]/TROUBLESHOOTING.md` | не трогать в рамках очистки |

Защищённый набор по умолчанию: `.tmp/`, `.trash/`, `.storage/`, `node_modules/` — источник истины `contracts.md` §2.

## Протокол обработки

1. **Снимок**: `scan.cjs --inventory --json` → объём и число файлов по каждому каталогу верхнего уровня.
2. **Классификация**: каждый кандидат → класс `R`/`C`/`D`/`P` + доказательство: команда восстановления для `R`/`C`, `--refs` для `P`.
3. **Список**: отчёт «путь · размер · класс · обоснование · обратимость» — до первого удаления.
4. **Удаление**: `R` и `C` — автономно, точными путями; `D` и `P` → эскалация.
5. **Контроль**: повторный `--inventory`; объём классов `D`/`P` не изменился, иначе — инцидент и разбор.
6. **Гейты**: ниже, по возрастанию стоимости; красный гейт → откат последнего шага.
7. **Гигиена**: класс `C` не возвращается молча → правило исключения в `.gitignore` или конфиге инструмента.
8. **Синхронизация**: `CHANGELOG.md`, `contracts.md`, реестр эволюции — в том же проходе.

## Жёсткие инварианты

1. Классификация артефакта опирается на обратимость: воспроизводимое удаляется автономно, невоспроизводимое идёт через эскалацию.
2. Защищённый набор каталогов не удаляется никогда, даже когда занимает основную долю объёма дерева.
3. Файл исходников удаляется только при нуле входящих рёбер в графе импортов от корней входа проекта.
4. Каждый удалённый объект назван точным путём с суммой освобождённого места; догадки в отчёт не попадают.
5. Состав и объём дерева фиксируются до и после прохода: необъяснимое расхождение — инцидент, а не результат.
6. После очистки гейты проекта зелёные; красный гейт → откат последнего шага и разбор причины.

## Гейты

- `node .agents/skills/clearing/scripts/scan.cjs --inventory` — дерево читается, классификация применима.
- `node .agents/skills/forge/scripts/forge.cjs check` — навык соответствует стандарту самообновления.
- `node scripts/arch-check.mjs` — границы слоёв не нарушены удалением.
- `npx tsc --noEmit` — типы сходятся после удаления.

## Ловушки

- Без VCS удаление необратимо → классы `D`/`P` решаются эскалацией, а не оценкой на глаз.
- Дерево может измениться извне между проходами → счётчики до и после; чужое изменение не приписывается навыку.
- Недостижимый модуль ≠ мусор: баррель-фасад слоя держит архитектурную конвенцию, которую проверяет arch-check.
- Воспроизводимый артефакт возвращается после первой же сборки → повторное появление не регрессия и не повод для новой записи.
- Конфиг dev-сервера может намеренно игнорировать каталоги `D`/`R` → «почистить, чтобы перестало тормозить» противоречит замыслу.
- Архив размером в сотни байт обычно битый или пустой → проверить содержимое до решения о судьбе вложенного.
- Каталог навыка может содержать собственный репозиторий → рекурсивное удаление внутри него ломает синхронизацию с центральным репозиторием.
- «0 импортов» не основание удалять документ: он может быть справочником для людей; доказательство даёт `--refs` по всему дереву.

- Правки спецификации, контракта, ловушек и рецептов по фактам работы.
- Гейты запускаются автономно; красный гейт чинится, пока причина выводится из контракта.

### Эскалация (стоп, один вопрос, до ответа — только read-only)

- Ломается публичный контракт или совместимость (данные, API, legacy).
- Поведение неоднозначно: варианты равно соответствуют правилам.
- Меняется эталон проверок (golden/baseline ожидаемых результатов).
- Деструктивные операции с данными или внешними системами.
- Проверка красная, причина не выводится из правил.
- Требуется обойти жёсткое правило или инвариант.

Формат эскалации: 1 вопрос · варианты · рекомендация · последствие выбора.

## Петля эволюции

- Новый класс мусора → строка в таблицу «Карта базы» и `contracts.md` §3 + ветка классификации в `scan.cjs` → `CHANGELOG.md`.
- Новый подтверждённый инвариант → правило в `POLICY` объекта `scan.cjs`, чтобы проверялось машиной, а не памятью.
- Ловушка перестала воспроизводиться → удалить, не копить дубли.
- Реестр эволюции: `node .agents/skills/observer/scripts/observer.cjs --log-history clearing <trigger> <improvement>`.

## Границы

- Не меняет содержимое проекта: код, документация и данные в рамках очистки не редактируются.
- Не запускает сборку ради очистки: артефакт сборки удаляется, а не пересобирается.
- Не выходит за пределы рабочего дерева; системные каталоги вне зоны ответственности.
- Не инициализирует VCS, не создаёт коммитов, не настраивает хуки.
- Защищённый набор не удаляется никогда: расширение набора — правка `contracts.md` §2, а не разовое исключение.
