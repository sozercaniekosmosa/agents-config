# Контракт навыка «Очистка проекта от лишнего»

Справочник для правок: что где лежит, что публично, что нельзя ломать.
Протокол и автономия — `../SKILL.md`.

## 1. Зона ответственности

- Навык судит о **принадлежности артефакта проекту**, а не о скорости среды.
- Ускорение и кэши как таковые — зона `/speed`; дублирование кода — `jscpd`/`/codebase-refactoring`.
- Единственная мутация навыка — удаление доказанного мусора и правка правил гигиены (исключения в конфиге).

## 2. Защищённый набор (policy)

Источник истины. Набор расширяется только правкой этого раздела.

| Путь | Почему защищён | Что теряется при удалении |
| --- | --- | --- |
| `.tmp/` | рабочие черновики, планы, очереди TASK | невоспроизводимое содержимое незавершённой работы |
| `.trash/` | бэкапы, снимки «до отката», замещённые файлы и каталоги | невоспроизводимое состояние, откат автора |
| `.storage/` | бэкапы базы проекта | единственная копия данных вне OPFS |
| `node_modules/` | зависимости | время установки; восстанавливается чисто |

- Защищённое не удаляется даже когда занимает основную долю объёма дерева.
- Классификация защищённого каталога — `D`, но политика выше любой классификации.

## 3. Карта артефактов (наблюдённое в проекте)

| Путь | Класс | Что это | Восстановление |
| --- | --- | --- | --- |
| `dist/` | `R` | сборка Vite | `npm run build` |
| `tsconfig.tsbuildinfo` | `R` | кэш инкрементальной сборки | появляется снова при `tsc -b` |
| `.dsh-tmp/` | `C` | кэш пакетного менеджера агента + дампы CLI | создаётся заново |
| `.agents/.cache/` | `C` | телеметрия observer, pre-pull бэкапы навыков | создаётся заново |
| `.agents/skills/*/.logs/` | `C` | логи навыков (уже в `.agents/.gitignore`) | создаётся заново |
| `prototypes/**` | `D` | одноразовые прототипы интерфейса | нет |
| `.trash/` | `D` | карантин бэкапов, снимков «до отката», замещённых версий | нет; возвращает только автор |
| `docs/*.json` | `P` | справочные спецификации для людей | нет; удалять нельзя |
| `[module]/guide.md`, `[module]/TROUBLESHOOTING.md` | `P` | конвенция документации модулей | нет; не мусор |

## 4. Контракт `scripts/scan.cjs`

- Read-only: ничего не удаляет, не пишет, не создаёт.
- Пути печатаются относительными от корня проекта.
- `node_modules`, `.git`, защищённый набор в обход не читаются (кроме явного `--refs`).

| Режим | Вход | Выход | exit |
| --- | --- | --- | --- |
| `--inventory` (default) | дерево | каталоги: класс, размер, файлы; пустые каталоги; подозрительные имена | 0 (`1` при `--strict` и находках) |
| `--graph` | `POLICY.entries` | модули с нулём входящих рёбер в графе импортов | 0 |
| `--refs <path>` | путь | файлы, упоминающие basename цели, с числом вхождений | 0 |
| `--json` | — | переключает вывод в JSON | — |
| `--strict` | с `--inventory` | находки становятся ошибкой | 0 / 1 |

- `POLICY` в шапке скрипта:

| Ключ | Смысл |
| --- | --- |
| `protected` | защищённый набор: класс `D*`, удаление запрещено политикой |
| `known` | известные артефакты: `cls`, `why`, `restore`; побеждает более длинный префикс |
| `entries` | корни входа для графа импортов |
| `scope` | каталоги, внутри которых строится граф |
| `ext` | расширения исходников |
| `genericStems` | основы имён, непригодные как игла поиска в `--refs` (`index`, `main`, …) |
| `skip` | каталоги, не обходимые при сканировании пустых и подозрительных имён |
| `suspicious` | маска имён-кандидатов: `*copy*`, `*backup*`, `*old*`, `*.log`, `*.tmp`, `~*` |

- Неизвестный артефакт получает класс `P` (безопасный дефолт), а не «мусор»: удаление требует явной записи в `known`.
- Размер каталога считается полностью, включая вложенные `skip`-каталоги: иначе верхний уровень недосчитывается.
- Каждая ветка классификации проверяема: новый класс → новая запись `known`.

## 5. Ловушки, подтверждённые на этом дереве

1. Корень проекта без `.git` → удаление необратимо, откат невозможен.
2. `.tmp/` уменьшился между проходами (58 → 25 файлов) без участия навыка → расхождение счётчиков нельзя приписывать очистке.
3. `src/index.ts` недостижим в графе, но держит конвенцию `hasModuleBarrel` из `scripts/arch-check.mjs` → недостижимость не приговор.
4. `vite.config.ts` намеренно игнорирует `.storage/`, `.tmp/`, `dist/` и `*.tmpdir/` → «почистить ради watcher» противоречит замыслу.
5. `dokument-proekta-*.zip` 239 байт → битый или пустой архив; решение только после проверки содержимого.
6. `docs/image-editor-prompt-conditions.json` — 0 импортов в коде, но ссылка в `guide.md` → документ для людей, класс `P`.
7. `.agents/` содержит собственный `.git` → рекурсивное удаление внутри ломает синхронизацию с центральным репозиторием.

## 6. Рецепты расширения

1. Новый класс мусора → таблица классов в `SKILL.md` + §3 здесь + ветка в `POLICY.known` `scan.cjs`.
2. Новый защищённый путь → §2 здесь + `POLICY.protected` `scan.cjs`.
3. Новый корень входа для графа → `POLICY.entries` `scan.cjs`.
4. Смена правил гигиены → правило в конфиге (например `.gitignore`) + §2 + строка в `CHANGELOG.md`.

## 7. Definition of done

- Отчёт до удаления: путь · размер · класс · доказательство · обратимость.
- Классы `D`/`P` не удалены без эскалации; защищённый набор цел.
- Повторный `--inventory` подтверждает неизменность объёма `D`/`P`.
- Гейты `SKILL.md` зелёные.
- `CHANGELOG.md` получил строку, реестр эволюции обновлён.
