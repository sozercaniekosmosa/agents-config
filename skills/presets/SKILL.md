# Пресеты-заготовки карточки: контракт и протокол

> [!IMPORTANT]
> Новая карточка с пресетами = одна запись в реестре плюс данные набора; UI не расходится по полям.
> Правка начинается с `track.cjs`/контракта и заканчивается `--update`, линтером и логом observer.
> Собственные артефакты навык обновляет сам; вопрос пользователю — только по пунктам эскалации.

## Назначение

- Задача: превратить «добавь пресеты на карточку X» в детерминированный проход: поле каталога → группы данных → реестр → палитра → гейты.
- Результат: пресеты появляются кнопкой «Пресеты» на любой карточке, чьё поле зарегистрировано; UI-компоненты не знают конкретных полей.
- Самообновление: `SKILL.md`, `references/contracts.md`, `CHANGELOG.md`, `state` синхронизируются в том же проходе, что и работа.
- Проверка: `forge check` + `presets-lint.cjs` + гейты проекта.

## Протокол добавления пресетов на карточку

1. **Вход**: `track.cjs` (дрейф — работа, не вопрос), `references/contracts.md`, `git status`.
2. **Поле**: найти запись в `src/shared/templates/fields/*.ts` → `id` и `title`. id узла карточки = `<fieldId>_<projectId>`.
3. **Данные**: каталог `src/shared/templates/presets/<domain>/`, одна группа = один файл, баррель `index.ts`; агрегатор `<domain>Presets.ts` задаёт порядок групп.
4. **Пресет**: `id` (kebab, уникален в наборе), `label` (что попадёт в карточку), `value` (смысл/подсказка в tooltip), `group` (раздел палитры), `tags` (скрытые ключи поиска).
5. **Реестр**: одна запись `{ fieldId, fieldTitle, presets }` в `CARD_PRESET_COLLECTIONS`; больше ничего в UI не меняется.
6. **UI**: кнопка появляется сама через `cardPresets.length > 0`; веток по полю не добавлять. Подпись палитры и title кнопки — нейтральные (не «жанровые»), если набор не жанровый.
7. **Верификация**: гейты ниже по возрастанию стоимости; `presets-lint` первым.
8. **Синхронизация**: `track.cjs --update`, строка в `CHANGELOG.md` (трекер), `observer --log-history`, гайды затронутых модулей, если поведение изменилось.

## Жёсткие инварианты

1. Данные и реестр живут только в `src/shared/templates/presets`; `components` не ветвится по title/id и не импортирует группы напрямую.
2. `fieldId` каждого набора существует в каталоге полей; `resolveCardPresets` матчит id по префиксу `<fieldId>_` и title строго по равенству после нормализации.
3. `id` уникален внутри набора и match `^[a-z0-9][a-z0-9-]*$`; `label`, `value`, `group` непустые; `label` без запятой.
4. В карточку добавляются только `label` через `", "`, без дублей (регистронезависимо); `value` в текст не попадает.
5. Поиск: `label` — по началу основы при любой длине; `description` — с основы ≥ 3 символов; скрытые `tags` — только при точной основе.
6. Одна группа = один файл; порядок групп в агрегаторе = порядок разделов палитры; модуль ≤ 400–500 LOC.
7. Единственный вход — кнопка «Пресеты»; клавиатурных шорткатов нет; пока палитра открыта, карточка не сохраняет устаревший текст.
8. Палитра и кнопка не привязаны к жанру: при нежанровом наборе «жанровые» формулировки заменяются нейтральными.

## Ловушки

- `tags` не участвуют в поиске по префиксу: иначе «при» цепляет фэнтези через тег «приключения»; тег совпадает только по точной основе.
- Короткий запрос не ищет по описанию и тегам: «пр» поднимал фэнтези через подсказку «Пророчество»; 1–2 символа матчат только названия.
- `value` — подсказка, а не вставляемый текст: в карточку уходит `label`.
- Дубликат `id` ломает `Set` выбора и React key: линтер — единственный быстрый сигнал.
- Запятая в `label` рвёт формат «поле через запятую».
- `resolveCardPresets` по title — только точное совпадение; подстрока не сработает (legacy-узлы без узнаваемого id).
- Правка базы без `--update` даёт дрейф — это сигнал синхронизации, а не ошибка.
- Baseline фиксирует хэши файлов, а не качество: качество проверяют линтер и гейты.
- Подписи палитры и кнопки нейтральные («Пресеты-заготовки», «Пресеты»): жанровые формулировки при нежанровом наборе линтер ловит как ошибку.

## Петля эволюции

- Новый класс поломки → `references/contracts.md` («Ловушки») + правило в линтере + строка в CHANGELOG.
- Новый рецепт (поле, группа, нежанровый набор) → `references/contracts.md`; протокол в этом файле не дублировать.
- Устаревший инвариант → удалить или переформулировать, не копить дубли.
- Дефект линтера (пропускает плохой набор) → правка `presets-lint.cjs` + строка в `CHANGELOG.md`.

## Границы

- `track.cjs --check/--report/--audit` и `presets-lint.cjs` — read-only; `--update` пишет только `state`, AUTO-блок, `CHANGELOG.md`.
- Не пишет UI-ветвления под конкретное поле и не меняет формат хранения карточки.
- Не придумывает данные пресетов: набор наполняется из задачи автора или каталога.
- Не трогает несвязанные карточки, БД и контракты соседних модулей.
